התמונות בתיקיות הביקורת הן תצוגות לבדיקה בענף. לא הוקם אתר Preview ולא בוצע Deploy. נתיבי HTML ייכנסו לאתר הציבורי רק לאחר תהליך האישור והמיזוג.

## תחזוקה: הוספת מוצר שמיני מאושר

1. לבדוק תחילה מה מוזג ל־main ומה אושר ב־Issue המוצר. `natural-edge-door-sign` שייך ל־`home-decor`; אין לפתוח קולקציה חמישית או להמציא תוכן/תמונה/מידות.
2. לשמור את מזהה המוצר, כתובת `products/<id>/` וכתובת `inquiry/?product=<id>` המאושרים. Breadcrumb ו־backCollection מובילים ל־`../../collections/home-decor/`.
3. להוסיף **כרטיס HTML אחד** ב־`collections/home-decor/index.html`, עם H2, תמונה מאושרת, srcset/sizes/מידות/ALT מתורגם ו־loading/decoding, תקציר וקישור טבעי לעמוד המוצר. אין להוסיף רשימת מוצרי בית.
4. להוסיף מפתחות HE/EN חדשים ל־`assets/js/language.js` עם עברית סטטית מקבילה ב־HTML. לשמר SEO ייחודי של המוצר. אין להוסיף קישורי hreflang לשפות שבאותו URL.
5. להעתיק את `CATEGORY_PRODUCT_MAP.json` לחבילת הביקורת של משימת המוצר החדשה, להרחיב שם את המפה ולעדכן את קבועי המוצרים/קבוצות בכלי הבדיקה הרלוונטיים. להפנות את `qa-collections-shared.cjs` למפה החדשה. לא לשנות מפות ודוחות של משימות קודמות, כולל חבילת WUL-019 לאחר מסירתה; כרגע helper הבדיקות קורא את המפה של WUL-019.
6. הוספת מזהה חדש ל־allowlist הטופס תתבצע רק במשימת המוצר המאושרת, לא כחלק משינוי קולקציות. ב־WUL-019 כל `inquiry/` ו־`attribution.js` נשמרו זהים לבסיס.
7. לעדכן baseline לבדיקות השימור לאחר שהמוצר נוסף לבסיס המאושר, ולעדכן ספירת 3+2+1+1 ל־4+2+1+1. להריץ שוב את כל מטריצות הקבלה, הקישורים, no-JS, הגלריה וה־mock payload. לשמור ראיות חדשות בספריית המשימה החדשה, לא לדרוס חבילת ביקורת קודמת.
